# FARS 解剖与对标：我们的设计要改什么

**用途**：本次大赛赛题核心参考 = Analemma（日行迹）的 FARS。本文件把 FARS 的可核实事实抽出来，逐条对标我们的 PaperSwarm 设计，并列出必须修正的地方。
**核实日期**：2026-09-29
**主要来源**：`analemma.ai/blog/introducing-fars/`（官方博客）、FARS 直播公开页面（`analemma.ai/fars`）、多家媒体报道交叉验证

## 0. 事实卡（只说核实得到的）

### 0.1 系统形态

| 项 | 事实 |
|---|---|
| 开发方 | Analemma（日行迹），2025-03 成立，创始人孙天祥（MOSS 大模型主开发者）；红杉中国、高榕创投等投资 |
| 定位 | 端到端 AI 研究系统，属 **AI4AI**（用 AI 做 AI 研究）范式 |
| 架构 | **多智能体系统，4 个专用 agent**：Ideation / Planning / Experiment / Writing |
| 协作机制 | 所有 agent 通过**共享文件系统**协作——它同时是工作空间和持久记忆。每个长周期任务在结构化项目目录内读写（`Idea.md` / `memory` / `experiments` / `results` / `references` / `latex`） |
| 规模机制 | **项目队列（Project Queue）**：Ideation 产出的假设通过自动审查后**串行**交给 Planning → Experiment → Writing；多条流水线并行。共享工作区让协作不依赖 agent 间直接通信，因此能扩展到大量并发项目 |
| 关键门控 | 假设必须**通过 automated review** 才进入后续流水线 |
| 算力 | 封装 **160 张 NVIDIA GPU** 集群作为实验 agent 的训练/推理工具 + 一批常用模型推理端点（支持数据合成、Agent 设计、LLM-as-a-Judge） |
| 学习机制 | 基于 **RLVR**（Reinforcement Learning from Verifiable Rewards） |
| 输出形态 | **短论文**：每篇聚焦单一、边界清晰的贡献；**鼓励报告负面结果**；不受篇幅与结构约束 |
| 设计第一性原理 | 研究系统的目的是**高效可靠地拓展知识边界**。只要假设合理，验证结果无论正负都构成知识 |
| 科研诚信 | 提交 arXiv 前**至少 3 位 5 年以上经验的研究者内审**，且所有提交**明确标注 AI 生成** |
| 代码 | GitLab `gitlab.com/fars-a`（公开提交过程） |
| 明确局限 | 目前主要限于 AI 领域（尤其 LLM）；**无法处理极度计算密集型实验或需要人工参与的任务**（如人工标注） |

## 1. 映射：FARS 四模块 → PaperSwarm 角色

| FARS 模块 | 职责（官方描述） | PaperSwarm 对应角色 | 我们额外加的 |
|---|---|---|---|
| **Ideation** | 文献调研、假设生成；输入是"多个研究方向"的文档；可访问开放论文与公开 GitLab 仓库 | `scout` — 候选筛选 + **复现假设生成** | 可行性预判门控（依赖可得性 + 算力估算） |
| **Planning** | 实验方案设计、基线/主实验规划、有效性评估方案、数据集与算力配置 | `planner` — **原设计缺失，本次补上** | 算力超预算的降规模路径 |
| **Experiment** | 代码自动编写、环境部署、任务执行与监控、结果收集分析；多种子并行、过程实时校验 | `engineer` + `analyst` | 沙箱资源上限；失败自修**有界**（FARS 未强调上限） |
| **Writing** | 论文全部分类撰写（摘要/引言/方法/结果/讨论/结论/参考文献）+ 生成图表 | `writer` + `typesetter` | ICLR 模板合规门控（页数 / 体积） |
| **（FARS 无）** | — | `adversary` 对抗审稿 | Evaluator-Optimizer 修订闭环 |
| **（FARS 无独立角色）** | 假设自动审查（gate） | `swarm.paper_evidence_rail` + 可行性门控 | **证据台账**：claim ↔ artifact SHA，产物层拦截 |
| **（人类）** | arXiv 提交前 3 人内审 | `PI`（human_agent）HITL | 候选圈定 + 超预算审批 + 放行 |

**FARS 用共享文件系统做记忆这件事，我们天然对齐**：JiuwenSwarm 的 team workspace 就是共享文件系统，证据台账、`repro-pack/`、`artifacts/` 全部落在里面；轨迹另由 `team_observability` 的 file exporter 落 `~/.jiuwenswarm/.trace`，资源报告从那里聚合。

## 2. 它给了我们一个真实的外部 KPI（之前定不出来）

FARS 的数据让我们第一次有了可量化的对标线。目标定为：

| 档位 | paperreview.ai 综合分 | 依据 |
|---|---|---|
| **及格** | ≥ 4.21 | 达到 ICLR 2026 人类投稿平均分 |
| **良好** | ≥ 5.05 | 达到 FARS 100 篇的平均分 |
| **优秀** | ≥ 5.39 | 达到 ICLR 2026 接收论文平均分 |

论文评测必须用 **venue = ICLR** 提交（该设置下 paperreview.ai 输出 1–10 综合分），否则拿不到可比分数。

## 3. 它暴露的、我们必须正视的差距

### 3.1 成本差距是数量级的（最大的现实问题）

FARS：**1.14 亿 token / 约 1,040 美元 / 篇**。

我们不可能匹配这个量级。必须明说：**我们是低预算版本**。压制手段只有四条，且都有代价：

| 手段 | 效果 | 代价 |
|---|---|---|
| 严格的前置可行性门控 | 避免把预算烧在跑不通的对象上 | 候选池命中率下降 |
| 模型分档路由（编排/仲裁用强模型，抽取/格式化用弱模型） | 大头在 worker，此处降本最有效 | 弱模型段落质量下降 |
| 收窄研究范围（单篇只做一个复现结论，不做多实验矩阵） | token 线性下降 | 论文贡献面变窄 |
| 硬预算闸门 `swarmflow_budget` | 杜绝失控 | 触顶即 run failed 且**不可续跑**（JiuwenSwarm 的既有行为），必须留余量 |

**行动**：把单篇预算目标设为 **≤ 100 美元 / ≤ 1,000 万 token**（比 FARS 低一个数量级），先在 Phase 2 用一次真实小规模运行实测单位成本，再回填这个数字。**这个数字在实测前是假设，不是承诺。**

### 3.2 FARS 自己承认的局限，恰好落在我们的场景上

FARS：「无法处理极度计算密集型实验或需要人工参与的任务」。

所以**不要试图复现需要大算力的论文**——这直接决定了复现对象的筛选标准：参数量小、单卡可跑、数据公开、训练时长以分钟计的对象。这条要写进 `scout` 的硬性筛选条件。

### 3.3 「规模才有意义」与我们的预算冲突

FARS 明确说：用少量样本评估 AI 研究系统是不充分的，所以它跑了 100 篇。

我们跑不了 100 篇。诚实的处理方式是**不假装有统计效力**：

- 主实验：完整跑通 **1 篇** ICLR 模板论文（证明链路端到端可用）
- 对照实验：小规模跑 **3–5 篇** 的 `scout` + `planner` 阶段，只统计**可行性预判准确率**与**单位成本**，不声称论文质量分布
- 技术文档中明确写：本系统论文质量分布无统计效力，结论限于"链路可行 + 成本可控"

### 3.4 FARS 输出"短论文、不受篇幅约束"，但大赛要 ICLR 模板

这是我们必须额外干的活：FARS 可以不守格式，我们不能。ICLR 模板合规（页数、字号、图表规范）由 `swarm.paper_latex_rail` 硬门控。另外 paperreview.ai **只分析前 15 页**——正文必须在 15 页内把贡献说清，参考文献超出不影响。

### 3.5 学术伦理的坑要预先堵住

FARS 已经因此被批评（"垃圾论文泛滥"担忧）。我们的对策，写进 `bind.md` 与技术文档：

- 论文显式标注 **AI 生成**
- 不自动投稿到任何公开平台；`swarm.paper_review_submit` 只提交到 paperreview.ai 做**预审**，且是**危险操作，强制 HITL 确认**
- 保留人工终审点（`PI`）
- 负面结果照实报告，不美化

## 4. 由此产生的 5 处设计修正

| # | 修正 | 原设计 | 修正后 |
|---|---|---|---|
| 1 | **补 `planner` 角色** | 只有 scout（筛论文）+ archaeologist（拉材料），**Planning 模块缺失** | 新增 `planner`：实验方案设计、基线/主实验规划、有效性评估方案、数据集与算力配置 |
| 2 | **补项目队列** | 单篇串行 | Project Queue：`scout` 持续产假设入队 → 通过门控者逐一启动流水线；并发由 `swarmflow_concurrency` 控制 |
| 3 | **成功指标改为外部基准** | 只有"产出合规 PDF" | 增加 paperreview.ai（venue=ICLR）分数档位：4.21 / 5.05 / 5.39 |
| 4 | **成本模型重建** | "预算取值待实测" | 以 FARS 的 1,040 美元/篇为参照，目标压到 ≤100 美元/篇；列明四条降本手段与代价 |
| 5 | **Ideation 升级** | scout 只"筛出可复现论文" | scout 产出**可验证的复现假设**（含预期反向结果），对齐 FARS 的 hypothesis 语义；同时这就是"复现与再分析"路线的合法研究贡献形态 |

## 5. 我们的差异化（技术创新点，写进技术文档）

FARS 已经是标杆，我们不能只做"缩小版 FARS"。真正能站住的差异点：

1. **证据台账（Claim–Evidence Ledger）**。FARS 的诚信机制是**事后人工内审**（3 位研究者）。我们做的是**事前结构性拦截**：论文中每个数值型 claim 必须绑定 artifact 的 SHA-256，未登记的数字在 LaTeX 编译门控处直接拦死。人工内审是概率性的，产物层校验是确定性的——这是我们最硬的一条差异。
2. **失败有界的自主复现循环**。FARS 未公开其重试上限策略。我们的 `engineer` 自修循环带 max_steps + token 预算 + 墙钟上限，且**失败必须如实上报，禁止降级为"伪造成功"**。
3. **对抗审稿闭环 + 外部 reward**。`adversary` 以结构化审稿意见驱动 `writer` 修订，轮次与分数停滞双重停止条件。FARS 未描述这一层。
4. **协调工程本身作为贡献**。FARS 的贡献是"能跑 100 篇"；我们的贡献可以是"**在 1/10 成本下保持链路可信**"——即 Coordination Engineering 视角的成本-可信度权衡，这正好是 openJiuwen 社区的主命题。

## 4. 与 FARS 的量级对比（诚实版）

FARS 公布的实测（2026-02-13 → 02-23 直播，来源见 `fars-benchmark.md` §0.2）：
**100 篇 / 114 亿 token / 104,000 美元 → 平均 1.14 亿 token、约 1,040 美元/篇**。

| 指标 | FARS / 篇 | 本系统 / 篇 | 比值 |
|---|---|---|---|
| 总 token | 114,000,000 | 10,318 | **约 1/11,050** |
| 成本（USD） | ≈ 1,040 | 0（本机推理） | — |
| 产出论文量 | 100 篇 | 1 篇（+3 篇前段） | — |

**必须同时说清的三件事，否则这组对比就是误导：**

1. **这不构成质量对比。** FARS 的 1.14 亿 token 换来的是 100 篇按 ICLR 标准均分 5.05 的短论文；
   我们这 1 万 token 换来的是**一篇 4 页的自指性论文**（研究对象就是本系统自身），
   实验是一个 120 维近共线设计下的 OLS vs Ridge 对照。**贡献规模不在同一量级。**
2. **token 少是"任务小"的直接结果，不是效率胜利。** 我们只写 7 个章节、只登记 11 个 claim、
   跑一个 0.5 秒的实验。把任务放大到 FARS 的规模，token 会随之上升——**上升多少未经实测**。
3. **成本 0 元的成立前提是"模型在本机"**。换到付费前沿模型，成本 = token × 该模型官方单价，
   而**我没有既准确又不变的价格数字**，所以这里不给估计值（见 §5）。

## 5. 成本口径：为什么写 0 而不是"未定价"

遥测层（`src/paperswarm/telemetry.py`）有一条刻意的设计约束：

> **不内置任何模型价格表。** 只有调用方显式给出单价（`price_per_1k_prompt` /
> `price_per_1k_completion`）才计算成本；否则记 `unpriced`，汇总里标 `cost_basis = "unpriced"`。

理由：价格是随时会变的外部事实。硬编进代码 = 埋一个会**静默失真**的数据源，
而纸面成本算错在"资源报告"这个交付物上是致命的。

在这个口径下，本机 Ollama 的 `0.0` 是**配置里写明的已知事实**（`configs/model.yaml`），
所以记 `priced / 0.0`，而不是"未定价"。

### 5.1 本次修掉的一个真实缺陷

**缺陷**：`scripts/full_paper.py` 记录调用时**没有把 profile 里的单价透传给遥测层**，
导致所有端到端全文运行的成本列都是 `unpriced / null`——尽管 profile 里明明白白写着 0.0。
`vertical_slice.py` 透传了，`full_paper.py` 漏了。

**修复**：在两处 `telemetry.record_call(...)` 中补上
`price_per_1k_prompt=client.config.price_per_1k_prompt` 与
`price_per_1k_completion=client.config.price_per_1k_completion`。

**验证**：修复后重跑端到端，`runs/paper-20260929-161913/run_summary.json` 中
`cost_basis` 由 `unpriced` 变为 **`priced`**、`cost_usd_total` 由 `null` 变为 **`0.0`**。
这条是"重跑验证改动"的直接证据，不是推断。

> 历史运行（`152903` / `153316`）的台账**保持原样，不回溯篡改**——它们如实记录的是修复前的行为。
> 台账不可改写在证据系统里是底线，包括对自己不利的记录。

## 7. 覆盖率与效力边界（不掩饰）

1. **样本量 = 1 篇完整论文 + 3 篇前段。** 单位成本 10,318 tokens 是**单次观测**，
   不构成分布，不能当作"期望成本"。至少需要跑 5–10 篇同类任务才谈得上均值与方差。
2. **运行间方差未测。** 三次全文运行的 tokens 是 8,859 / 8,892 / 10,318——
   最后一篇因为多了一轮门控重写而偏高。**门控重写是 token 方差的主因，其期望轮数未测**（当前观测：7 章里 1 章需 2 轮）。
3. **口径不含工具调用成本。** `paper-*` 全文路径 `tool_calls_total = 0`（章节写作走
   `full_paper.py` 的直接调用，不经过 Agent 循环）；只有竖切片路径走 Agent 循环（6 次工具调用）。
   两条路径的成本不可直接横向比。
4. **时延数字绑定本机硬件。** P95 19.6 s/次 是 RTX 4060 Laptop + 7B Q4 的结果，
   换硬件会变，不具迁移性。
5. **付费模型的成本仍是空白。** 要填这个数，只能：查目标平台官方定价页 →
   按实际计费口径换算每千 token 单价 → 写进 `configs/model.yaml` 的对应 profile。
   **在拿到官方数字前，这里保持空白。**
